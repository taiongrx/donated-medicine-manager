# แผนกู้คืนระบบจากภัยพิบัติ (Disaster Recovery Plan - DRP)
## ระบบบริหารจัดการคลังยาบริจาค (Donated Medicine Manager)
### โรงพยาบาลสมเด็จพระยุพราชสายบุรี (รหัสหน่วยงาน: 10690)

---

## 1. วัตถุประสงค์และเป้าหมายการกู้คืน (Recovery Targets)

แผนฉบับนี้กำหนดกรอบเวลาและเป้าหมายในการกู้คืนฐานข้อมูลและระบบสารสนเทศคลังยาบริจาค เพื่อป้องกันการสูญหายของประวัติการรับเข้า-เบิกจ่ายเวชภัณฑ์ และรักษาความถูกต้องของบัญชีสต็อกสำหรับสำนักงานการตรวจเงินแผ่นดิน (สตง.):

- **Recovery Point Objective (RPO)**: **< 1 ชั่วโมง** (ข้อมูลธุรกรรมย้อนหลังจะต้องสูญหายไม่เกิน 1 ชั่วโมง)
- **Recovery Time Objective (RTO)**: **< 15 นาที** (ระบบจะต้องกลับมาเปิดให้บริการแก่ผู้ป่วยได้ภายใน 15 นาทีหลังจากเกิดเหตุ)

---

## 2. นโยบายการสำรองข้อมูล (3-2-1 Backup Strategy)

ระบบใช้มาตรฐานการสำรองข้อมูลแบบ 3-2-1 สอดคล้องตามมาตรฐานความปลอดภัยสารสนเทศโรงพยาบาล:

1. **3 Copies**: ข้อมูลจะต้องมีอย่างน้อย 3 ชุด (Production Database, Local Daily Snapshot, Offsite Archive)
2. **2 Media Types**: จัดเก็บบนสื่อบันทึกข้อมูลอย่างน้อย 2 ชนิด (NVMe/SSD บนเซิร์ฟเวอร์ และ Network Attached Storage - NAS / Cloud Storage)
3. **1 Offsite Location**: มีสำเนาสำรองเก็บไว้นอกห้องจ่ายยาอย่างน้อย 1 ชุด (ศูนย์คอมพิวเตอร์หลัก รพ. หรือ NAS กลาง)

### กำหนดการสำรองข้อมูลอัตโนมัติ (Automated Backup Schedule)
- **รอบการสำรองข้อมูล**: ทุกวันเวลา **12:00 น.** (พักเที่ยง) และ **17:00 น.** (ปิดรอบจ่ายยาประจำวัน)
- **สคริปต์ที่ใช้**: `scripts/backup_database.sh` (Linux) หรือ `scripts/backup_database.bat` (Windows)
- **ระยะเวลาการเก็บรักษา (Retention Policy)**: จัดเก็บย้อนหลัง **90 วัน** บนเซิร์ฟเวอร์ และ **5 ปี** สำหรับรายงานสรุปประจำปี (Annual Audit Report)

## 3. ขั้นตอนการกู้คืนข้อมูลทีละขั้นตอน (Step-by-Step Restoration Runbook)

### กรณีที่ 1: กู้คืนบนเซิร์ฟเวอร์เดิม (ฐานข้อมูลเสียหาย / ข้อมูลผิดพลาด)

#### 🐧 บนระบบ Linux Server:
```bash
# 1. หยุดการทำงานของ Backend ชั่วคราวเพื่อป้องกันการเขียนทับ
docker compose stop backend

# 2. รันสคริปต์กู้คืนฐานข้อมูล
sudo chmod +x scripts/restore_database.sh
sudo ./scripts/restore_database.sh

# 3. เริ่มต้นการทำงานของ Backend อีกครั้ง
docker compose start backend

# 4. ตรวจสอบสถานะความพร้อมของระบบ
curl http://localhost:8000/healthz
curl http://localhost:8000/readyz
```

#### 🪟 บนระบบ Windows Server / PC:
```cmd
1. ดับเบิ้ลคลิกไฟล์ "scripts\restore_database.bat" (Run as Administrator)
2. เลือกรหัสไฟล์สำรองที่ต้องการกู้คืน (ระบบจะแสดงรายการตามวัน-เวลา)
3. สคริปต์จะตรวจสอบความสมบูรณ์ของไฟล์ (SHA-256) และนำเข้าข้อมูลแทนที่
4. สั่งเริ่มระบบใหม่ผ่าน "start_service.bat"
```

---

### กรณีที่ 2: เซิร์ฟเวอร์พังเสียหายสิ้นเชิง (Bare-Metal Disaster Recovery)

1. **เตรียมเครื่องใหม่หรือเครื่องลูกข่ายทดแทน** (ติดตั้ง Windows 10/11 หรือ Ubuntu + Docker)
2. **Clone โค้ดระบบจาก GitHub**:
   ```bash
   git clone https://github.com/taiongrx/donated-medicine-manager.git /opt/donated-medicine-manager
   cd /opt/donated-medicine-manager
   ```
3. **นำไฟล์สำรองล่าสุดจาก NAS หรือ Flash Drive ฉุกเฉิน** มาวางในโฟลเดอร์ `backups/`
4. **รันตัวติดตั้งระบบ**:
   - บน Linux: `sudo ./install.sh`
   - บน Windows: คลิกขวาที่ `install.bat` -> Run as administrator
5. **รันคำสั่ง Restore ข้อมูล**:
   - บน Linux: `sudo ./scripts/restore_database.sh`
   - บน Windows: `scripts\restore_database.bat`
6. **ทดสอบระบบ**: เปิดเว็บเบราว์เซอร์และทดสอบสืบค้นสต็อกยา ตรวจสอบยอดคงเหลือว่าตรงกับใบล่าสุด

## 4. แผนการซักซ้อมการกู้คืนระบบ (Annual DRP Drill)

- **ความถี่**: ซักซ้อมทุก **6 เดือน** (เดือนมีนาคม และ เดือนกันยายนของทุกปี)
- **ผู้เข้าร่วม**: เภสัชกรคลังยาบริจาค, เจ้าพนักงานเภสัชกรรม, และทีม IT รพ.
- **เกณฑ์การประเมิน**:
  - [ ] สามารถกู้คืนข้อมูลทดสอบได้ภายในเวลา 15 นาทีหรือไม่
  - [ ] ข้อมูลประวัติการรับเข้าและยอดคงเหลือมีความถูกต้องครบถ้วน 100% หรือไม่
  - [ ] เครื่องลูกข่ายหน้าต่างจ่ายยาสามารถพิมพ์ฉลากต่อได้โดยไม่ติดขัดหรือไม่
